🎯 THE RESEARCH HYPOTHESIS

When multiple industrial modalities (vision, telemetry, history) provide
evidence of an anomaly, the system should:

  1. Estimate the QUALITY of each modality's evidence
  2. DYNAMICALLY adjust trust based on quality
  3. FUSE evidence using trust weights (not fixed averaging)
  4. Produce CALIBRATED confidence (honest about reliability)
  5. LEARN from human feedback via trust prior updates

Result: System degrades gracefully when modalities fail.

📊 HOW THE SYSTEM WORKS (30-Second Overview)

Frontend (React):
  User inputs: sensor_value, image, asset_id
  ↓
Backend (FastAPI):
  Receives HTTP POST /predict
  Calls: result = run_inference(image, sensor_value, asset_id)
  ↓
ML Core (PyTorch) - 8 Step Pipeline:
  1. Vision detector     → 0.91 (anomaly score)
  2. Telemetry detector → 0.63
  3. History detector   → 0.82
  4. Quality estimation → q_vision=0.91, q_telemetry=0.52, q_history=0.94
  5. Trust gating       → w_vision=39%, w_telemetry=18%, w_history=43%
     (Formula: w_i = (q_i × p_i) / Σ(q_j × p_j))
  6. Fusion             → z_fused = 0.39×0.91 + 0.18×0.63 + 0.43×0.82 = 0.81
  7. Calibration        → calibrated_confidence = 0.78
  8. Return JSON        → Complete InferenceResult
  ↓
Backend:
  Logs result to database
  Returns JSON to frontend
  ↓
Frontend:
  Displays: ANOMALY DETECTED (78% confidence)
  Shows: Per-modality contributions
  Shows: Quality scores + explanations

KEY INSIGHT:
  Telemetry had LOWER quality (0.52 vs 0.91/0.94)
  → Its weight AUTOMATICALLY reduced (18% vs ~33% if equal)
  → System detected degradation without rules
  → Purely data-driven adaptation

🎯 CRITICAL PRINCIPLES

DON'T: quality = model_confidence
DO:    quality = input_properties (blur, noise, recency, etc.)

DON'T: w_vision = 0.5 (hard-code)
DO:    w_i = (q_i × p_i) / Σ(q_j × p_j) (data-driven)

DON'T: Report "ECE improved" without measuring
DO:    Report actual ECE or "NOT YET MEASURED"

DON'T: Ignore missing modalities
DO:    Renormalize weights over available modalities
